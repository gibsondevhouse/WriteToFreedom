# Write to Freedom

A responsive novel-planning app with an original African-inspired white SVG crest. Characters opens a searchable, sortable list of four sample characters and the signed-in author's saved characters. New character creates a blank, private record and opens the same editable encyclopedia profile used for every character. All fields can be edited in place; Save changes persists them to D1. Factions and Locations have their own directories; the remaining home-page sections and global search are disabled placeholders.

Run `npm install`, `npm run build`, and `npm run dev` using Node 22. The local preview is at `http://127.0.0.1:4173` with a separate development database in the ignored `.sites-runtime` directory. The local server injects a development identity; the production Worker requires the Sites authenticated-user header. Production queries are scoped to that user. Tests use isolated in-memory SQLite databases: `npm test`.

Frontend source is in `public/`. The character directory lives in `public/characters/`; its default sample records are in `data.js` and `profile-data.js`. Model family names are used without version numbers: [Claude](https://docs.anthropic.com/claude/docs), [GPT](https://openai.com/research), [DeepSeek](https://deepseek.com/en/index.html), and [Gemini](https://deepmind.google/models/gemini/). All sample biographies, affiliations, and relationships are fiction.

`npm run build` bundles the frontend assets with the Cloudflare-compatible Worker into `dist/server/index.js`. Every profile is rendered by the Worker at `/characters/{id}/`. Old editor URLs redirect to the corresponding profile. Sample edits are stored as private overrides, so each author has their own cast; default sample data remains unchanged. The complete editable schema is shared in `public/characters/template.js`.

The D1 schema is in `db/schema.ts`; schema-only migrations are generated with `npm run db:generate` and stored in `drizzle/`. Sites applies these before deployment. Character creation is idempotent, all queries are owner-scoped, and version checks prevent stale edits from overwriting newer saves. The form preserves text on save errors and warns before leaving with unsaved changes. Browser storage is not used as the source of truth.

Identity uses first, middle, and last name fields that accept Unicode, hyphens, spaces, and apostrophes. Display names are composed from those fields. Legacy full names are retained intact in the first-name field until the author chooses how to split them. Story role and moral alignment use dropdowns, with existing custom values preserved. Factions can be selected from the sample factions or created inline and saved privately for reuse; save the character to apply the selected faction. Existing free-text affiliations remain available until replaced or cleared.

Factions reuses the character directory layout at `/factions/`. Every existing faction opens an editable article profile with an infobox, history, ideology, organization, notable members, resources, customs, and alliances. New faction opens a blank profile. Founder and leader link to character profiles; affiliated members are derived from characters’ faction selections. Faction renames appear throughout character profiles and dropdowns. Private faction documents use version checks and the `faction_profiles` table, preserving preexisting faction IDs and memberships.

Locations is a combined directory at `/locations/`, with search, type filters, and sorting. Every city has a country. Areas can belong to a city or another area, and landmarks can belong to a city or an area; their city and country are inherited through that ancestry. The list shows ancestor paths and descendant counts. New location adds only a name, type, and required parent to D1. Parent type and ownership are validated on the server. The sample list uses places from the existing fictional cast. Countries and cities open editable article profiles. Areas and landmarks currently use the location list editor.

Country profiles live at `/locations/countries/{id}/`, with a national infobox and article sections for etymology, history, geography, government, economy, demographics, and culture. Flags, coats of arms, and maps accept optional HTTPS image URLs. Capital and largest-city choices are limited to the country’s own cities; its cities and landmarks are shown automatically. Private documents use `country_profiles` with optimistic version checks. Country names update the existing directory entry without changing IDs or parent relationships.

## Approved profile standard

The character profile is the design baseline for all entity profiles. Characters, factions, countries, and cities reuse the same breadcrumb-only navigation, sticky save bar, editable infobox name, collapsible article headings, dimmed collapsed titles, collapsible infobox groups, and icon-only field visibility menus. Field visibility is saved separately from content: hidden and collapsed controls remain mounted, and their values are preserved. Collapse state is temporary; field visibility persists per author.

- `server/profile-components.js` owns page layout, section headers and visibility menus, infobox groups, field wrappers, choice controls, and the editable profile name.
- `public/profiles/profile.css` and `editor.css` own the approved visual styling; the old character CSS paths are compatibility imports.
- `public/profiles/controls.js` owns disclosure, field visibility, custom dropdown values, name focus, validation reveal, textarea sizing, and hash navigation.
- `public/profiles/editor.js` owns the shared faction/country/city save flow and image previews. The character editor uses the same controls and retains its relationship and inline faction-creation adapter.
- `public/profiles/choices.js` supplies dropdown suggestions with custom values. `schema.js` supplies validated field-visibility allowlists. Each entity retains its own template and server rules.

Extend these components for future profile work rather than copying a page or rebuilding controls. Keep entity-specific features in their adapters: faction membership is derived from characters; country capitals and largest cities belong to that country; cities retain a required country; area and landmark ancestry is preserved. `tests/profile-standard.test.mjs` covers the shared structure and save/reopen behavior across all four profile types.

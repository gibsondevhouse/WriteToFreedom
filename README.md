# Write to Freedom

A responsive novel-planning app with an original African-inspired white SVG crest. Characters opens a searchable, sortable list of four sample characters and the signed-in author's saved characters. New character creates a blank, private record and opens the complete editable template. Save character persists it to D1. Custom profiles include an Edit character link. Other home-page sections, browsing, and global search remain disabled placeholders.

Run `npm install`, `npm run build`, and `npm run dev` using Node 22. The local preview is at `http://127.0.0.1:4173` with a separate development database in the ignored `.sites-runtime` directory. The local server injects a development identity; the production Worker requires the Sites authenticated-user header. Production queries are scoped to that user. Tests use isolated in-memory SQLite databases: `npm test`.

Frontend source is in `public/`. The character directory lives in `public/characters/`; its read-only sample records are in `data.js` and `profile-data.js`. Model family names are used without version numbers: [Claude](https://docs.anthropic.com/claude/docs), [GPT](https://openai.com/research), [DeepSeek](https://deepseek.com/en/index.html), and [Gemini](https://deepmind.google/models/gemini/). All sample biographies, affiliations, and relationships are fiction.

`npm run build` regenerates the four sample profiles and bundles the frontend assets with the Cloudflare-compatible Worker into `dist/server/index.js`. Custom profiles are rendered by the Worker at `/characters/{id}/`; the editor is at `/characters/edit/?id={id}`. The complete editable schema is shared in `public/characters/template.js`.

The D1 schema is in `db/schema.ts`; schema-only migrations are generated with `npm run db:generate` and stored in `drizzle/`. Sites applies these before deployment. Character creation is idempotent, all queries are owner-scoped, and version checks prevent stale edits from overwriting newer saves. The form preserves text on save errors and warns before leaving with unsaved changes. Browser storage is not used as the source of truth.

Identity uses first, middle, and last name fields that accept Unicode, hyphens, spaces, and apostrophes. Display names are composed from those fields. Legacy full names are retained intact in the first-name field until the author chooses how to split them. Story role and moral alignment use dropdowns, with existing custom values preserved. Factions can be selected from the sample factions or created inline and saved privately for reuse; save the character to apply the selected faction. Existing free-text affiliations remain available until replaced or cleared.
